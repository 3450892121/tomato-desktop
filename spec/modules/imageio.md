# 模块：图片读写（imageio）

## 目标
可靠地把常见图片文件解码为像素缓冲、把处理结果按手机版规则编码落盘，并复刻手机版的尺寸/格式行为。

## 范围
- 解码：PNG、JPG/JPEG、WebP、BMP 等浏览器内核支持的常见格式（含带透明通道）。
- 编码规则（与 APK 一致）：
  - `gilbert` 模式 → **JPEG，画质 95**（帮助文案：使用 jpg 保存以大幅减小体积）。
  - 其余 5 种模式 → **PNG，无损**（帮助文案：其他混淆 png 格式不变）。
- 尺寸规则（与 APK 一致）：
  - `b`（方块）模式：宽/高不足 32 倍数时填充到 32 的倍数（补黑/透明），**不裁剪回原尺寸**，输出尺寸因此可能变大。
  - 其余模式：尺寸不变。
- 元数据：不读写 EXIF，不保留方向标记之外的元数据（与手机版一致）。
- 大图保护：解码前检查像素总量，超限给出明确提示而非崩溃（对应手机版的「内存不足」系列提示）。
- 缩略图：`makeThumbnailFromBytes` 直接从图片字节出缩略图（`createImageBitmap` 后缩放绘制到目标小画布并立即 `close()`），**全程不摊开整图 RGBA 缓冲**——「添加文件」只需要尺寸与 42px 缩略图，不值得为此把整图摊开两次（40MP 图瞬时约 320MB，拖文件夹时逐张串行会冻结界面）；返回原图尺寸，错误文案与像素上限判断与解码主路径逐字一致。**HEIC/HEIF/HIF 不适用**：Chromium 内核不解码，那类输入靠主进程 libheif 引擎返回裸像素，只能用 `makeThumbnail(pixels, …)`。

## 输入 / 输出
- 输入：图片文件路径/字节流、模式标识、编码参数（JPG 画质等）。
- 输出：像素缓冲（供引擎）、编码后的文件字节流。

## 非目标
- 不做格式转换工具、不缩放、不裁剪、不做 EXIF 编辑。

## 依赖的其他模块
- 依赖 `engine`（确定输出尺寸与格式）；被 `ui`、`batch` 调用。
