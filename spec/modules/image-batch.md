# 模块：图片批量工具（image-batch）

> 更新记录：v0.1（2026-09-19）新增模块。需求由用户 2026-09-19 提出（工具箱大扩展）。
> 本文件覆盖四个同批立项的小工具（各自独立目录、互不依赖），放一起写是因为它们同属「日常图片杂活」这一组。

## 共同约定
- 四个工具全部为**纯 Chromium 内核 canvas 实现**，零新增依赖（不引入任何图像库）。
- 每个工具有自己的专用文件对话框与测试夹具前缀，避免测试互相污染（见 `AGENTS.md` 的教训记录）。
- 样式只引用 `shell/theme.css` 变量，类名前缀各自独立（`bren-` / `wm-` / `st-` / `gs-`）。

## 1. 批量重命名（batch-rename）
目录 `src/tools/batch-rename/`，id `batch-rename`，order 42，图标 🏷️。

- 四种规则：**序号**（前缀/起始/位数/保留原名）、**查找替换**（可开正则）、**加前后缀**、**按日期**（`YYYY/MM/DD/HH/mm/ss` 模板，用文件修改时间）。
- **排序方式**（v2.9.0 起）：按添加顺序 / **修改时间 旧→新** / **修改时间 新→旧**。排序直接决定列表顺序与序号分配（`序号`规则即按此顺序编号）；取不到修改时间的文件排在最后，时间相同保持原顺序（稳定排序）。
- **执行前先预览**「原名 ｜ 修改日期 → 新名」，逐条显示修改时间与体积。
- **执行前确认**（v2.9.0 起）：点「开始重命名」先弹确认框，写明将改名/跳过/自动编号/覆盖各多少条，并列出前几条「原名 → 新名」；取消则一步不动。
- **命名冲突处理**（v2.9.0 起，用户 2026-09-21 明确要求，替换原先「有冲突即禁止执行」）：
  - **跳过**（默认）：目标已存在的文件保持原名不动，日志记为「跳过」；
  - **替换**：目标已存在时覆盖它（旧文件被删除，界面有红字警告）；
  - **自动编号**：目标已存在时在名字后加 `(1)`、`(2)`… 直到不重名（与主进程 `uniqueTargetPath` 的「另存」命名习惯一致）。
  - 批内两个文件抢同一目标名：跳过/替换模式下两条都拒绝（替换会造成本批互相覆盖，属数据损坏）；自动编号模式下第一条保留、其余加编号。
  - 规则非法（如非法正则）与文件名非法（Windows 保留名/非法字符/超长）仍然只跳过该条，并在行上写明原因。
- **统计与日志**（v2.9.0 起）：执行后显示「成功 N ｜ 跳过 N ｜ 失败 N（含覆盖 N、自动编号 N）」；可点「导出日志」把逐条明细（序号/原文件名/原路径/修改时间/新文件名/结果/说明）以 UTF-8 BOM CSV 存到源文件所在目录（重名自动加序号，`重命名日志-<时间戳>.csv`），路径显示在界面上。
- **直接改用户原文件名**（不产生副本、不进回收站），界面上有明确红字提醒。
- 主进程新增 IPC `fs:rename-batch`，其安全性由两阶段改名保证：
  1. 先把所有源文件改成同目录临时名（`.tomato-rename-<ts>-<i>`）；
  2. 再把临时名改成目标名。
  这样**链式改名**（`001→002`、`002→003`）与**互换名**都不会互相踩；跨盘自动回退为复制+删除，失败时尽力把临时名还原回原名（不让文件「消失」）。
  目标已存在且不属于本批源文件时：**默认跳过并报「目标文件已存在」**；仅当该条带 `overwrite: true`（界面选了「替换」）时，才在阶段 2 把旧目标先挪成 `.tomato-rename-bak-<ts>-<i>` 备份、改名成功后再删备份，失败则把备份还原回原位——保证「覆盖」不会两头空。

## 2. 加水印（watermark）
目录 `src/tools/watermark/`，id `watermark`，order 44，图标 💧。

- 水印类型：**文字**（内容/颜色/透明度/旋转/描边）与**图片**（印章 LOGO，可选透明度/旋转/大小）。
- 位置：**九宫格**（左上/上/右上/左/中/右/左下/下/右下）+ **平铺**（可设间距）。
- 大小按图宽百分比换算（`computeFontSize`），保证不同尺寸的图观感一致；文字默认带描边，浅色背景上也看得清。
- 选中列表项展示**原图 / 加好水印后**对比预览，参数一改预览跟着变。
- 输出命名 `原名_水印.png`（或 JPG）。

## 3. 长图拼接（stitch）
目录 `src/tools/stitch/`，id `stitch`，order 46，图标 🧩。

- **竖拼**（从上到下，聊天记录/网页截图场景）与**横拼**（从左到右）。
- **统一尺寸**：竖拼统一宽度、横拼统一高度；**只缩不放**（放大只会糊），未填目标时取列表里最大值。
- 间距、外边距、对齐（居中/起始/末尾）、输出格式（PNG / JPG+画质）。
- **一次产出一张图**（把列表里的图合成一张，不是每张各自处理）；列表顺序即拼接顺序，支持上下移动调整。
- 超限保护：单边 > 16384 或总面积 > 1.6 亿像素时 `limitExceeded` 报错并阻止执行（而不是让 canvas 崩掉）。
- 间距/外边距处统一铺白底（JPG 不支持透明）。

## 4. 九宫格切图（grid-slice）
目录 `src/tools/grid-slice/`，id `grid-slice`，order 48，图标 ▦。

- 预设：九宫格 3×3（默认）/ 四宫格 2×2 / 竖切三条 1×3 / 横切三条 3×1 / 自定义行列数。
- 切缝宽度、外圈留白、切缝颜色（宽度 > 0 时描在每块朝内的边上）、编号方式（按行/按列，两位补零）。
- 选中项显示**原图 + 切分网格线与编号叠加**的预览，并提示「共几块 / 每块多大 / 输出几个文件」。
- 汇总按「处理图片张数」与「产出文件数」分别说清楚（一张图产出 N 个文件）。
- 图太小（块 < 8px 或 ≤ 0）时给出警告并阻止执行。

## 非目标
- 不做图片编辑（裁剪/滤镜/修图）——见「图片变清晰」等工具。
- 不做 PDF 相关（见 PDF 工具）。
- `batch-rename` 不做文件夹整体搬移与移动（只改名，不换目录）。

## 已知限制
- 批量重命名**不可撤销**（不进回收站），所以界面必须把预览与提醒做足。
- 拼接的超大长图受 Chromium canvas 上限约束（已在界面提前拦截）。
- 水印与拼接、切图都会重编码图片，会剥离 EXIF（隐私更安全，但色彩可能轻微变化）。

## 验证结论（2026-09-19 实测回填）
- **批量重命名**：四种规则实测通过（`假期.png → 照片_001.png`、`IMG_1234.jpg → 照片1234.jpg`、正则 `\d+→#`、按日期 `20260919`）；安全性用例——目标已存在被拒（`done=0`、报「目标文件已存在」、两文件内容原样）、链式 `1→2、2→3` 正确、互换名正确、无临时文件残留。
- **加水印**（640×420 底图，产物均回读为 640×420）：文字右下角（透明 60、旋转 −20、描边）变化 **8471 px（3.15%）**、变化框落在右下 [253,293,612,419]；透明印章居中 **11431 px（4.25%）**、中心≈图心；平铺 **41150 px（15.31%）**。
- **长图拼接**（夹具 200×100 红 / 100×200 蓝 / 300×150 绿，间距 10）：竖拼 300×470、统一宽度 150 得 150×370、横拼 620×200，**输出尺寸 = 计算值 = 落盘解码尺寸**；采样像素顺序正确（含间距白）、JPG 容差 1。
- **九宫格切图**（300×300 四角纯色夹具）：3×3 无缝得 9 块各 100×100、27 处采样与原图逐点一致；3×3 缝宽 10 得 9 块各 93×93（余 1px 丢弃）且内侧边为白缝；2×2 按列编号 `_01,_03,_02,_04`。
- `--imgbatch-test`：`ok:true`（四个工具的纯逻辑断言 + 真实处理 + 界面走查全过）。

## 验证结论（v2.9.0 回填，2026-09-21）
- **排序**：夹具甲/乙/丙修改时间依次 `T-3d/T-2d/T-1d` → 「旧→新」得 甲,乙,丙、「新→旧」得 丙,乙,甲、「按添加顺序」保持对话框给的 丙,乙,甲；无时间的文件沉底、同一时刻保持原顺序；`formatDateTime` 空时间返回 `''`。
- **排序决定编号**：切「旧→新」后按前缀序号改名，产物 `测试重命名UI_001/002/003.png` 内容分别为 `甲甲/乙乙/丙丙`（最旧 = 001）——磁盘回读逐条对上。
- **确认弹窗**：点「开始重命名」必弹；点「取消」后三个夹具原样未动（状态栏「已取消，没有改动任何文件」）；点「确认改名 3 个」才真改名；弹窗概要文案与逐条「原名 → 新名」均正确。
- **冲突三策略**（同一批夹具切三种模式）：「跳过不改」预览显示为不改且执行按钮禁用；「替换已存在文件」显示「覆盖」标签 + 红字警告条；「自动编号」把 `占位.png` 的目标改成 `占位(1).png`（标签「自动编号」），真改名后 `占位.png` 内容仍为 `OLD2`、`占位(1).png` 内容为 `AAA2`。
- **备份式覆盖**（主进程直调）：`测试重命名O2.png → 测试重命名O1.png`（O1 已存在）带 `overwrite:true` → `done=1、overwritten=1`，O1 内容变 `NEW`、O2 消失；不带该标记时仍按老规矩拒绝；两种情况下夹具目录都不新增 `.tomato-rename-*` 残留（前后快照比对）。
- **日志导出**：`重命名日志-<时间戳>.csv` 落盘，UTF-8 BOM + 表头 `序号,原文件名,原路径,修改时间,新文件名,结果,说明` + 3 条明细（含完整路径与 `成功`），路径回显在界面上。
- `--imgbatch-test`：`ok:true`。

## 踩坑记录
- 界面测试的**汇总断言**要求每个 check 都带 `ok` 字段：`cleanFixtures` 只返回 `{before, after}` 会让整体判为失败（已补 `ok`）。
- 测试里读期望值要用**用例定义**（`run.expect.sizes`），别写成解析结果（`r.expect.sizes`）——后者是 undefined，报错信息还会指向别处，很难一眼看出。
- 水印的**印章夹具前缀**不能以「测试水印」开头，否则会被主对话框的 `startWith` 一起选进来，导致张数断言多一张。
- v2.9.0 新增三条：
  1. **`{...live}` 是快照**：`result.checks.真实改名 = { ok, ...live }` 一旦写在新增用例之前，后面塞进 `live` 的字段全丢了（表现为「断言莫名 false、明细还看得到」）——汇总赋值必须放在所有用例之后。
  2. 测「目标已存在」时，**占位文件不能以本工具夹具前缀（`测试重命名`）开头**：否则对话框会把它一起选进列表，它就成了本批源文件（链式改名放行），根本不是冲突。占位文件正好要放在「新名字」上，而新名字是规则算出来的，注意别顺手带上夹具前缀。
  3. 残留检查（`.tomato-rename-*`）要用**跑前跑后快照比对**：共用夹具目录里可能有更早被中断的运行留下的陈年临时文件，绝对断言会冤枉本次代码（本次就遇到一个几小时前的 `.tomato-rename-…-1`）。
