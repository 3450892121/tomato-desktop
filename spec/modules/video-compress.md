# 模块：视频压缩（video-compress）

## 目标
把视频体积压小到能发出去（微信/邮件），两种用法：按**画质档**压，或按**目标体积**压（如压到 10 MB 以内）。拖进来、选一档、一键压完，结果直接对比「原大小 → 新大小」。

## 范围
工具目录 `src/tools/video-compress/`，id `video-compress`，左侧名「视频压缩」，group `video`，order 62，图标 🗜️。

- 批量导入：多选 / 拖拽文件 / 拖入文件夹（自动取其中支持的视频）。
- 输入格式：ffmpeg 可解的主流视频（与「视频格式转换」同一份扩展名清单）。
- **两种压缩方式**：
  - 画质档：质量档（高质量 CRF 20 / 标准 CRF 23 / 小体积 CRF 28）+ 分辨率档（保持原样 / 2160p / 1080p / 720p / 480p / 360p）+ 可选「去掉声音」。
  - 目标体积：目标 MB 档（5/10/20/50/100/200）+ 音频码率档（64k / 96k / 128k / 去掉声音）。
- 输出：固定 MP4（H.264 + AAC，`+faststart` 便于边下边播）；保存到原视频旁（重名自动加序号，不覆盖），可用「设置 → 输出目录」覆盖。
- 结果：每项显示「→ 新文件名（新体积）」，汇总成功/失败数量与最后一条错误；进度可取消。

## 关键技术决策
1. **目标体积用两遍编码**：先按目标体积反推视频码率（`planTargetBitrate`，预留音频占用与 3% 封装余量），第一遍只分析写 passlog、第二遍才落盘。单遍 ABR 的体积误差通常 ±10~20%，两遍能压到目标附近。
   - 主进程新增 IPC `ffmpeg:convert-two-pass`；passlog 放系统临时目录、两遍共用一个前缀，**跑完（含失败）一定清理**，不留垃圾。
   - 进度按两遍各占一半折算（0~50% / 50~100%）。
2. **不达标自动重跑一次**：压完用 `verifyTarget` 校验，超出目标 5% 且尚未重试过时，用 `retryBitrate`（×0.85，下限 50 kbps）降档重跑**一次**；重跑前先删掉未达标的产物，避免留下两份输出。
3. 编码参数一律走 `shared/ffmpeg.js` 的参数拼装器（`videoEncodeArgs` / `twoPassArgs` / `scaleToHeightArgs`），不各写一套。

## 非目标
- 不做视频剪辑（裁剪/拼接/加字幕/变速）——本期只压体积。
- 不做 HEVC/AV1 等更高效的编码（本机与目标用户的兼容性优先，H.264 最稳）。
- 不做「无损压缩」（视频无损压缩基本压不动，没有实际意义）。

## 已知限制
- 目标体积是**目标不是保证**：内容复杂度不同的视频，实际落点会有偏差；自动重跑一次后仍可能略超，界面如实显示「预计/实际」。
- 目标体积模式固定输出 MP4；想换容器请用「视频格式转换」。
- 两遍编码耗时约为单遍的 1.6~1.8 倍，长视频更明显。
- 视频压缩依赖 ffmpeg 加装包（缺失时给出放置说明，其余工具不受影响）。

## 依赖
- `shared/ffmpeg.js`（探测、单遍/两遍转码、进度、取消、编码参数）；`settings`（输出目录）。
- 不依赖任何其它工具。
