# 模块：工具箱框架（toolkit）

## 目标
让软件能"越用越长"：多个工具共存、左侧一键切换；新工具接入成本最低（复制模板 + 注册一行），且不影响既有工具。

## 范围
- **工具注册表**（`app/src/shell/registry.js`）：唯一的工具清单。每行一个工具模块，按 `order` 排序显示；另导出 `GROUPS`（分组定义：图片 / 视频 / 文档）。
- **左侧导航分组**：工具声明里带 `group`，左侧列表按分组显示：
  - `image` → 「图片」：图片混淆、图片压缩、图片变清晰、图片格式转换；
  - `video` → 「视频」：视频播放器、视频格式转换、动图与视频互转；
  - `doc` → 「文档」：PDF 转格式。
  - 分组顺序取 `GROUPS` 定义（图片 → 视频 → 文档）；组内按 `order` 升序；空分组不显示；未声明 `group` 的工具自动归入末尾的「其它」组（容错，不影响启动）。
  - **可折叠（v1.5.0 起；v1.8.0 起默认折叠）**：每条分组标题带图标、名称与工具数量，**点一下收起该组工具、再点一下展开**，靠高度过渡做平滑动画（不是硬切换显隐）；
    - **默认全部收起**：没人设置过时，列表只显示分类标题与数量，避免工具变多后侧栏一长串、信息过载；
    - 收起状态存进 `settings.collapsedGroups`（数组＝用户点过的结果；`null`＝从没设置过→按默认全部收起），下次打开保持；
    - 切到某工具时，其所在分组会**临时展开**（只影响这次显示，不改用户偏好、不写设置）；列表每次重渲染仍按用户偏好来。
- **工具页保活**：切换工具**不再卸载上一个工具**——
  - 每个工具一个 `.tool-page` 容器：首次进入时 `mount` 一次；切走时整页从文档取下（DOM 与工具内部状态留在内存，不销毁、不重新挂载）；切回来原样放回。
  - 因此切走再切回时：已选文件列表、当前选中项、输入内容、预览画面、滚动位置、顶栏提示与参数信息**全部保持**，不重置、不消失。
  - 同一时刻文档里只有当前工具的页面（其余页面在内存中）——工具与自动化测试用 `document.querySelector` 找元素时不会误抓到别的页面。
  - **LRU 回收（v1.9.0；v2.1.1 起按用户反馈改为「额度只按动过的页算」）**：保活的**「动过」页**上限 `MAX_ALIVE_PAGES = 5`（含当前页），
    超出时淘汰**最久没用过**的那一页——先调它的 `unmount()`（清理事件 / 进度订阅 / UI 订阅），再整页丢掉；下次进入时重新 `mount`（内容从头开始）。
    - **「动过」判定**：用户在这一页里点按 / 打字 / 拖入过文件（`pointerdown / click / keydown / input / change / drop / paste`）才算动过；只是切过来看一眼、滚一滚不算。
    - 「没动过」的页没有内容可丢：切走时**静默释放**（不占额度、不提示，下次进入重新 `mount`，与首次进入完全一样）——
      修掉「随便看看有什么功能，就把别处用过的东西挤掉」的体验问题（用户反馈原话）。
    - 当前页永不淘汰；**「动过」的页**被回收时，状态栏会补一句「（用过的工具较多，上次的内容已自动释放）」，避免用户误以为文件丢了。
    - 目的：保活换来的「切回不丢状态」不能以内存无限增长为代价（如图片混淆会持有已选图片的像素数据）。
    - 日常使用（在图片混淆 + 一两个转换工具之间来回）远低于上限，不会触发回收。
    - 后台任务不受影响：被回收页面里的任务归属队列、照常跑完（见 `task-queue.md` 的硬契约），页面只是退掉自己的 UI 订阅。
      要触发回收得「一边跑长任务、一边连着动过 5 个其它工具」，属于极端操作。
  - 生命周期约定：`mount(container, ctx)`（首次进入一次）→ `activate()` / `deactivate()`（可选，每次切入/切出调用；切走时若该页「没动过」，`deactivate()` 之后紧接着 `unmount()` 释放）→ `unmount()`（页面被销毁 / 被 LRU 回收时调用）。
  - 工具里挂在 `window` / `document` 上的交互（如快捷键）必须先用 `ctx.isActive()` 判断自己是不是当前页，隐藏时让位。
  - **状态与进度按页记账（v2.10.1 起）**：`ctx.setStatus/setInfo` 会记到本页并在切回时恢复；**进度遮罩全局只有一个**——`ctx.showProgress/hideProgress` 始终记到本页、只有当前页才真的动遮罩，`switchTool` 按新页记下的状态恢复或关闭（切走还在跑的工具时遮罩一定会被关掉，切回来又能接上；页面被 LRU 回收后同样由 shell 兜底）。工具侧不必也无法靠自己「回收后补关」，照常用 `ctx.showProgress/hideProgress` 即可。
  - 取舍：保活意味着「动过」页的内存（如已选图片的像素数据）在切换后仍占用，换「切回不丢状态」；没动过的页不驻留、不占内存，超额部分由上面的 LRU 回收兜住。
- **工具声明约定**：每个工具导出统一结构：
  ```
  {
    id: 'obfuscate',            // 唯一标识（英文小写）
    name: '图片混淆',            // 左侧列表显示名
    icon: '🍅',                 // 列表图标（emoji 或内置 SVG 路径）
    group: 'image',             // 左侧分组：image（图片）/ video（视频）/ doc（文档）
    order: 10,                  // 组内排序（小的在前）
    styles: ['./tools/obfuscate/styles.css'],  // 工具自带样式（首次进入时自动加载）
    mount(container, ctx),      // 渲染界面到容器（只在首次进入时调用一次）；ctx 提供框架通用能力
    activate(), deactivate(),   // 可选：每次切入 / 切出时调用（全局交互要在这里让位 / 恢复）
    unmount()                   // 页面被销毁时清理（当前页面常驻，正常切换不会调用）
  }
  ```
- **框架上下文 ctx**（由 shell 提供）：状态提示、参数信息、进度显示、文件对话框、设置读写、剪贴板、图片解码/编码等通用能力；
  额外提供 `ctx.isActive()`——工具当前是否显示在右侧（挂到 window/document 上的交互必须先判断它）。
- **工具自包含**：工具的界面、逻辑、样式、专属算法都放在自己的文件夹里；工具之间禁止互相 import。
- **共享能力**：跨工具复用的（图片读写、文件封装、设置）统一放 `app/src/shared/`。
- **新工具模板**：`app/src/tools/_template/` 空白模板（接入步骤见 `shell/registry.js` 顶部注释）。

## 导航手动排序（v2.6.0 引入；v2.11.0 起改为「长按拖动」，移除排序模式）
- **长按拖动**：**不需要**进入任何排序模式——在左侧列表里**长按条目约 400ms** 即拿起拖动：拖**分组标题**＝移动整个分组（主项目），拖**组内工具**＝在本组内移动（子项目）；松手按视觉序落位并落盘。
  - 实现要点：`pointerdown` 起 400ms 长按计时器，到时立即 `beginDrag`（被拖条目马上升起玻璃卡作为「已拿起」反馈）；计时未到就移动 ≥4px 视为放弃按压（计时器取消，不进入拖拽）。
  - **点击不受影响**：未超过长按时间就松手＝普通点击——点工具条目切换工具、点分组标题展开/收起（照常写 `collapsedGroups` 偏好）。`pointerdown` 的 `preventDefault` 拦不住 click，行为由原有 click 处理器接管。
  - **拖后防误触**：真实指针拖完浏览器仍会派发 click——navsort 在 nav 的 **capture 阶段**拦下「拖拽结束后 500ms 内」的 click（`stopPropagation`），避免「拖完顺手切了工具/把组收起来了」；窗口外的迟到 click 因超出时间窗自然放行。
- **独立排序**：主项目（分组）与子项目（组内工具）各自独立排序——拖分组头移动整个分组块；工具条目只在**本组内**拖动（不跨组，分组归属由工具声明决定）；「其它」组永远排在最后（它由未声明 group 的工具自动聚合而来，不参与分组排序，但组内工具可排序）。
- **排序持久化**：`settings.navOrder`：
  - `null` = 从没排过序（默认，按 GROUPS 定义顺序 × 组内 `order` 字段）；
  - `{ groups: [...分组id], tools: { <组id>: [...工具id] } }` = 用户拖出的顺序；每次拖放成功立即落盘完整快照。
  - **sanitize 规则（渲染前统一净化，任何非法形状回退默认）**：未知分组 id / 未知工具 id 忽略；新分组按注册顺序追加在已排序分组之后；组内新增工具按 `order` 追加在尾部；工具 id 只能落回 registry 声明的组（手改 settings.json 也无法把工具「走私」到别的组）；`groups` 里出现 `other` 一律忽略（其它组永远置底）。
- **启动默认工具**：启动自动打开「排在最前的分组」里的**第一个工具**——排序第一位即「最常用」，启动直接进它的工具页，并只展开这一个分组，其余分组仍按 `collapsedGroups` 偏好显示。
  - 从没排过序（`navOrder = null`）时等于默认序的第一个分组（图片 → 图片混淆），与旧版行为一致。
  - 修复的用户问题：旧版固定打开「图片混淆」，它所在分组被「切工具时自动展开所在分组」规则重新打开——用户把它收起来过也没用，看起来像设置失效。
- **交互细节**：Pointer Events 自绘拖拽（无新依赖）；长按拿起后被拖条目升起玻璃卡、同级兄弟用 transform 平滑让位（兄弟高度不齐也成立——让位偏移＝被拖块高度＋间距，与兄弟自身高度无关）；接近列表上下边缘自动滚动；系统「减少动态效果」时让位/落位动效降为瞬时（沿用 components.css 的全局规则），拖拽跟随不受影响。
- **视觉（v2.11.0 调整）**：工具条目悬停显示六点抓手（24px 缩进区内，不挤文字）、条目/标题悬停 grab 光标——随时暗示「长按可拖」；被拖块升起玻璃卡、其余条目轻微淡出（视线聚焦）。折叠箭头保持在标题左侧（长按拖动后不再有「排序中箭头右移」的专属视觉）。
- **恢复默认顺序**：侧栏底部「↺ 恢复默认顺序」按钮**只在 `settings.navOrder` 非空（用户排过序）时显示**，点一下清回 `null` 并按 GROUPS × order 默认序重渲染；没排过序时不占地方。
- **裁剪与折叠的取舍（v2.7.0）**：`.tool-group-items` 平时保持 `overflow: hidden`（折叠动画要用），**只在拖拽进行中**（`.is-drag-active`）放开，避免玻璃卡外阴影与兄弟让位被裁——被收起的分组内容是 `visibility: hidden`，放开也不会露出来。
- **降级**：若任何路径触发导航重渲染（如导入设置），防御性先结束拖拽再渲染，绝不带着拖拽状态重建 DOM。

## 输入 / 输出
- 输入：工具模块清单（注册表）、用户点击左侧列表、用户拖拽排序（写 settings.navOrder）。
- 输出：工具界面的挂载/卸载；活动工具的样式加载与回收；左侧列表渲染顺序。

## 非目标
- 本期不做插件市场、热插拔、第三方动态安装（工具随安装包一起发布）。
- 不做工具间通信总线（确有需要时再基于 ctx 扩展）。

## 依赖的其他模块
- 依赖 `ui`（布局与样式令牌）、`settings`（通用设置）；被所有工具依赖（通过 ctx）。
