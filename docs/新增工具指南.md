# 新增工具指南

> 目标：让「加一个新功能」变成低成本、不碰老代码的日常操作。
> 现有工具：`图片混淆`（src/tools/obfuscate）｜`PDF 转格式`（src/tools/pdf-convert）｜`文档格式转换`（src/tools/doc-convert）｜`图片压缩`（src/tools/compress）｜`图片变清晰`（src/tools/enhance）｜`图片格式转换`（src/tools/img-convert）｜`视频格式转换`（src/tools/video-convert）｜`动图与视频互转`（src/tools/sticker）｜`音频格式转换`（src/tools/audio-convert）｜空白模板：`src/tools/_template`

## 一、目录约定

```
app/src/
├─ shell/          框架（工具注册表、左侧导航、工具页容器、设计令牌、组件库）—— 一般不用动
│  ├─ theme.css        设计令牌（颜色/字号/间距/圆角/动效节奏）
│  ├─ components.css   通用组件库（btn / input / select / card / modal / progress，含统一动效）
│  └─ shell.css        框架布局（侧栏、分组折叠、工具页容器）
├─ tools/          工具目录：一个工具一个文件夹，自包含
│  └─ <工具标识>/
│     ├─ index.js      工具声明（名称/图标/排序/样式/mount）
│     ├─ ui.js         界面与交互（只做界面，不写业务逻辑）
│     ├─ styles.css    专属样式（颜色字号必须用 shell/theme.css 变量）
│     └─ core/         业务逻辑与算法（与界面解耦，方便单独测试）
└─ shared/         跨工具复用能力（图片读写、文件封装、设置）—— 新工具也用这里的
```

## 二、加一个工具：五步

以新增「图片压缩」为例（标识 `compress`）：

1. **复制模板**
   把 `app/src/tools/_template/` 复制为 `app/src/tools/compress/`（`_template` 本身不要改）。

2. **改声明**（`compress/index.js`）：
   ```js
   export default {
     id: 'compress',            // 唯一标识（英文小写）
     name: '图片压缩',           // 左侧列表显示名
     icon: '🗜️',                // 图标（emoji 即可）
     group: 'image',            // 左侧分组：image（图片）/ video（视频）/ audio（音频）/ doc（文档）
     order: 20,                 // 组内排序，数字小的排前面
     styles: ['../tools/compress/styles.css'],
     mount, unmount
   };
   ```
   > 分组在 `src/shell/registry.js` 的 `GROUPS` 里定义（图片 → 视频 → 文档）；左侧列表按分组显示小标题，组内按 `order` 升序，空分组不显示。要加新分组，先在 `GROUPS` 里加一行，再给工具声明填对应 `group`。

3. **写界面**（`compress/ui.js`）：在 `mount(container, ctx)` 里渲染你的界面并绑定事件（**只会调用一次**，工具页会被框架保活、切走不销毁）；
   顶部状态提示用 `ctx.setStatus(...)`，通用进度用 `ctx.showProgress(...) / ctx.hideProgress()`，
   文件对话框用 `ctx.openImages() / ctx.saveFile()`；
   按钮/输入框/卡片等通用组件直接用 `shell/components.css` 的类名（`btn btn-primary`、`input`、`select`、`card` …），动效节奏别自己写死时间。
   - 挂在 `window` / `document` 上的交互（快捷键等）必须在 `deactivate()` 里停掉、`activate()` 里恢复，或用 `ctx.isActive()` 判断自己是不是当前页（否则在别的工具里也会抢按键）；
   - 临时资源（定时器、blob URL、进度订阅）在 `deactivate()` 里释放；`unmount()` 负责「页面被销毁」的清理——正常切换不会调用它，但页面被 LRU 回收时会调用（见下）。

4. **写逻辑**（`compress/core/`）：算法与业务逻辑放这里，别写进 `ui.js`；
   需要图片解码/编码时用 `src/shared/imageio.js`。

5. **注册**（`app/src/shell/registry.js`）：加两行——
   ```js
   import compress from '../tools/compress/index.js';   // ← 加这行
   export const TOOLS = [
     obfuscate,
     compress                                            // ← 加这行
   ];
   ```

完成后重新启动软件：左侧列表会自动出现「图片压缩」，可正常切换使用。
**不需要修改任何既有工具或框架代码**（这也是验收标准 A9 的内容）。

## 三、必须遵守的约定

- 先补 spec：在 `spec/modules/` 写清该工具的目标/范围/输入输出/非目标，再写代码（见 AGENTS.md）。
- 工具之间**禁止互相 import**；要复用的能力放 `src/shared/`。
- 样式只用 `shell/theme.css` 里的变量，类名加工具前缀，避免冲突；通用组件别重写（用 `shell/components.css`）。
- `mount` 在每次「页面被创建」时调用：动过的页切走再切回只是一次（保活，切走只是从文档取下、状态留在内存），**表单一类的状态天然保留**，别在 `mount` 里做「每次进来都要重置」的假设。
- 保活只保「动过」的页（用户点按 / 打字 / 拖入过才算，只是切过来看一眼不算）：没动过的页**切走即释放**（下次进入重新 `mount`，与首次进入一样）；
  动过的页最多同时保活 5 页，超出会按 LRU 回收最久没用过的那页——那一刻会调 `unmount()` 清理并丢掉页面，下次进入重新 `mount`（内容从头开始）。
  所以 `mount` 必须能把界面从零建好，`unmount` 必须把资源清干净。
- 全局交互（窗口快捷键、进度订阅、定时器）必须在 `deactivate()` 让位、`activate()` 恢复，或在回调里先问 `ctx.isActive()`。
- 开发完照例跑冒烟自检并提交：`git commit -m "feat: 新增图片压缩工具"`。

## 四、常见问题

- **左侧没出现新工具？** 检查 `registry.js` 是否加了两行、`id` 是否重复。
- **样式不生效？** 检查 `styles` 路径（相对 `src/shell/index.html`，即 `../tools/<标识>/styles.css`）。
- **切换工具后报错？** 多半是 `unmount` 没清理定时器/事件，或界面里残留了对旧 DOM 的引用。
- **想先做个能点的空壳？** 只做第 1、2、5 步就能在左侧看到入口（界面显示模板内容）。
