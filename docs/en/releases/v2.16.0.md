# v2.16.0 release notes

[Docs](../../README.md) · [Full changelog](../../../CHANGELOG.md) · [中文](../../zh/releases/v2.16.0.md) · [Releases](https://github.com/3450892121/tomato-desktop/releases/tag/v2.16.0)

Released: 2026-10-18

## Highlights

### 1. Connect agents from inside the app

Open the app → **System → Agent Setup**:

- pick DSH / Qoder / Trae / WorkBuddy / ZCode and click **Connect**;
- click **Check setup**: it really starts MCP, counts the tools (41 expected), and names the failing step;
- **Remove** asks for confirmation and withdraws both the config and the Skill (backups kept).

Equivalent to double-clicking the one-click scripts in the app folder. No JSON editing, no commands, no Node.js.

### 2. One-click setup for five clients

| Client | After setup |
|---|---|
| DeepSeek Harness (DSH) | Fully quit and restart DSH |
| Qoder | Fully quit/reopen and start a new conversation |
| Trae (CN / international) | Fully quit/reopen and start a new task |
| WorkBuddy | Fully quit/reopen; click **Trust** once in MCP manager |
| ZCode | Fully quit/reopen; press Ctrl+K and confirm the MCP toggle |

Each client has its own Remove action; it touches only its own entry, backs up first, and preserves other MCP servers / providers.

### 3. Safer setup scripts

- Backups never overwrite each other (same-second runs get numeric suffixes);
- Read-back verification after writing, with automatic rollback;
- Invalid JSON is left byte-identical;
- Re-running setup is idempotent; removal can be repeated;
- Skill install/removal keeps backups.

## Verification

- `npm test` green (including 21 MCP tests and 16 setup-script tests);
- On a real machine, all five clients went through connect → real tool call in chat → remove → re-connect;
- `--smoke-test`: all 24 tools rendered.

## Upgrade

Download the new zip, unzip into a new folder, and copy the old `userdata\` over. **After upgrading, open System → Agent Setup and click "Connect" once again** for your client (the folder name changed, so the old path is gone), then restart that client. Only the latest release is kept; older versions remain reachable via git tags.
