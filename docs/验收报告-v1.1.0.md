## A13 Office→PDF 与 PDF→Word ⚠️ 部分通过

**未装加装包分支（已通过）**
- `.docx` → PDF：内置降级成功，输出 A4（596×843 pt）单页，**27,229 字节**，回读渲染确认有正文文字像素；单份约 **378 ms**
- `.xlsx` → PDF：内置降级成功，A4 单页，**21,396 字节**，回读渲染确认有表格内容；单份约 **384 ms**
- 界面测试（真实点按钮）：2 个文档 → `转换完成：成功 2 个（内置转换，版式可能有偏差；装加装包可高保真）`，产出 2 个 PDF 且读回页数 ≥1
- PDF → Word（未装加装包）：状态 `PDF → Word 需要 LibreOffice 加装包…`，**未产出任何 .docx** ✓（防预期落差）

**已装加装包分支（已通过，2026-09-18 实测）**
- 加装包来源与体积：LibreOffice 26.2.6（清华镜像 MSI 356 MB → 解包后 **1522 MB**），放置于 `addons/libreoffice/`
- 自动检测：`libreoffice:status` 返回 `where: "addon"`；界面上显示「✓ 已检测到 LibreOffice（加装包）」
- `.docx` → PDF（soffice 高保真通道）：单页、**存在正文文字像素**、30,346 字节，首次 36.2 s（含首次创建配置目录）
- PDF → Word（`--infilter=writer_pdf_import`）：产出 **6,262 字节**、以 `PK` 开头的合法 OOXML 包且含 `word/document.xml`，9.4 s
- 界面实测（真实点按钮）：Word/Excel→PDF `转换完成：成功 2 个`；**PDF→Word `转换完成：成功 7 个`，落盘 7 个 .docx**（对应列表里 7 份 PDF）
- 证据：`%TEMP%\tomato-pdf-test.json`（libreoffice 步骤）、`%TEMP%\tomato-pdf-ui-test.json`、截图 `shot-p06/p07`

**踩坑与修复（重要）**：加装包放在发布路径（`release\番茄图片混淆-桌面版-v1.x.x-win64\addons\…`）时，PDF 导入过滤器会加载失败（`source file could not be loaded`），而同一份文件放短路径正常（已排除路径长度与文件完整性因素）。**修复**：转换前自动用目录联接（junction，无需管理员权限）把加装包映射到短且纯 ASCII 的路径（`%TEMP%\tomato-lo\libreoffice`）再启动 soffice；打包态复测已恢复（见下方“打包产物复测”）。用户无需做任何额外操作。
